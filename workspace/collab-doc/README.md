# 多人协作文档（离线可编辑 · CRDT 合并 · 锚定评论 · 修订时间线）

零依赖实现（仅 Node.js 内置模块 + 原生 Web API），前端与服务器同容器运行。

## 功能与需求对应

| 需求 | 实现 |
|---|---|
| 断网后仍能编辑 | 所有编辑先应用到本地 CRDT 并写入 `localStorage`；断网期间操作进入待同步队列，页面刷新/重开也不丢 |
| 恢复连接后合并插入/删除/格式 | 文本用 **RGA** 序列 CRDT（删除=墓碑，插入按全局唯一 id 定序），格式用 **LWW 标记**，三者都是可交换、幂等的操作，重连后双向补发即收敛 |
| 较晚同步不覆盖他人已确认内容 | CRDT 的数学性质：操作可交换且幂等，迟到的操作只会"合并进来"，不存在覆盖语义（测试 2 验证） |
| 评论锚定到文字范围 | 锚点指向**字符 id** 而非偏移量（相对位置），并发编辑后仍落在正确文字上 |
| 文字被拆分/删除 → 可解释悬空 | 评论记录创建时的原文 `quote`，实时对比当前覆盖文字，区分 5 种状态：`已锚定` / `已拆分（中间插入新内容）` / `部分悬空（部分被删）` / `悬空（全部被删）` / `已变更`，并显示原文与当前文字 |
| 允许重新挂接 | 悬空评论点"重新挂接"，在文档中选中新范围即可，作为评论的 LWW 更新同步给所有人 |
| 一致的修订时间线 | 服务器为每个操作分配全局递增 `seq`，每个操作批次形成一个修订（含快照），所有客户端看到同一时间线 |
| 恢复历史版本 | 恢复 = 服务器生成一批普通的删除/插入/格式操作，**作为新修订**进入操作流，与他人的并发编辑按 CRDT 规则自然合并，不会回滚掉别人的内容（测试 5 验证） |
| 容器化一起运行 | 单一 `Dockerfile`（服务器直接托管前端静态文件），另附 `docker-compose.yml` |

## 运行

```bash
# 本地
npm start          # http://localhost:8080  （PORT 环境变量可改端口）

# 测试（8 项集成测试：同步/离线合并/评论悬空/格式合并/恢复/重启持久化）
npm test

# Docker
docker build -t collab-doc .
docker run -p 8080:8080 -v collab-data:/app/data collab-doc
# 或
docker compose up --build
```

打开 `http://localhost:8080`（可加 `?doc=xxx` 使用不同文档），多开几个窗口即多人协作；开 DevTools 离线模式可验证断网编辑与重连合并。

## 架构

```
collab-doc/
├── shared/crdt.js      # 共享 CRDT：RGA 文本 + 相对位置锚点 + 格式 LWW + 评论状态解析
├── server/server.js    # HTTP 静态服务 + 手写 RFC6455 WebSocket + 全局 seq + 修订/快照/恢复 + JSON 落盘
├── public/             # index.html / app.js / style.css（contenteditable 编辑器）
├── test/test.js        # 多客户端集成测试（含模拟离线客户端）
└── Dockerfile / docker-compose.yml
```

### 同步协议

- 客户端连接时发送 `hello{clientId, doc, lastSeq}`，服务器回 `welcome{ops: seq>lastSeq 的操作, revs}`；
- 客户端补发离线队列（按 `opId` 去重，服务器端也去重）；
- 每个操作批次被服务器赋予连续 `seq` 并形成修订，广播给房间内所有客户端；
- 客户端本地持久化 `{lastSeq, allOps, pending}`，刷新页面后离线可用。

### 关键设计取舍

- **不用任何 npm 依赖**：WebSocket 协议、CRDT、前端均为手写，镜像构建无需联网安装依赖，`node:20-alpine` 即可运行。
- **RGA 文本**：实现简单、删除不丢信息（墓碑）；已知局限是极端并发下可能出现字符交织（interleaving），对协作文档场景可接受。
- **格式 = 范围标记的并集**：同一属性键在覆盖同一区段的多个标记间按 `(ts, author)` 取最后写者，支持"加粗→取消加粗"。
- **评论/格式更新按 id LWW**：同一评论被两人同时修改时，全系统收敛到同一结果。
- **恢复快照只含文本+格式**：评论不随恢复回滚——被恢复操作删掉锚定文字的评论会按规则进入可解释的悬空状态，可重新挂接。

## 已知限制（演示级）

- 无鉴权与权限控制，`clientId` 自报；单进程内存 + JSON 落盘，未做水平扩展；
- 修订快照为全量文本，适合中小文档；
- 编辑器基于 contenteditable + 前后缀 diff，IME 组合输入已做基本处理，复杂嵌套富文本（表格、图片）未支持。
