# 多人协作文档（离线可编辑 · CRDT 合并 · 锚定评论 · 修订时间线 · 成员治理）

零依赖实现（仅 Node.js 内置模块 + 原生 Web API），前端与服务器同容器运行。

## 功能与需求对应

| 需求 | 实现 |
|---|---|
| 断网后仍能编辑 | 所有编辑先应用到本地 CRDT 并写入 `localStorage`，按**批次**组织；断网期间批次进入待同步队列，页面刷新/重开也不丢 |
| 恢复连接后合并插入/删除/格式 | 文本用 **RGA** 序列 CRDT（删除=墓碑，插入按全局唯一 id 定序），格式用 **LWW 标记**，三者都是可交换、幂等的操作，重连后双向补发即收敛 |
| 较晚同步不覆盖他人已确认内容 | CRDT 的数学性质：操作可交换且幂等，迟到的操作只会"合并进来"，不存在覆盖语义 |
| 评论锚定到文字范围 | 锚点指向**字符 id** 而非偏移量（相对位置），并发编辑后仍落在正确文字上 |
| 文字被拆分/删除 → 可解释悬空 | 评论记录创建时的原文 `quote`，实时对比当前覆盖文字，区分 5 种状态；并显示原文与当前文字 |
| 允许重新挂接 | 悬空评论点"重新挂接"，在文档中选中新范围即可，作为评论的 LWW 更新同步给所有人 |
| 一致的修订时间线 | 服务器为每个操作分配全局递增 `seq`，每个操作批次形成一个修订（含快照），所有客户端看到同一时间线 |
| 恢复历史版本 | 恢复 = 服务器生成一批普通的删除/插入/格式操作，**作为新修订**进入操作流，与他人并发编辑按 CRDT 规则自然合并 |
| **按空间的四角色治理** | owner / editor / commenter / viewer；邀请、改角色、移除仅 owner 可做，四角色命令矩阵在浏览器与服务器共用同一判定内核 `shared/gov.js` |
| **撤销访问作为一等冲突** | 断连排队的批次在重连时按**当前授权纪元**整批原子授权：整批放行或整批拒绝；被拒批次绝不发布、不产生修订，完整进入可读/可复制的**隔离草稿**，仅本人与 owner 可见；权限恢复后必须**显式重新提交** |
| **共享审计台账** | 每次成员变更、授权纪元推进、批次隔离/放行、回滚/越权回滚都写入与内容修订**共用同一单调 `seq`** 的台账，故台账与修订之间有全局无歧义顺序 |
| **全程幂等** | 成员变更用 `mId`、内容批次用 `batchId`、单操作用 `opId` 去重，幂等索引与结果均落盘；重试、重复投递、进程重启都不会重复执行成员变更、重复应用批次或重复记账 |
| **旧空间平滑升级** | 无成员元数据的旧文件保留全部内容/批注/修订；首个连接者在单个临界区内原子认领为唯一 owner 并立即落盘，并发首开也只产生一个 owner，不重写既有数据 |
| 容器化一起运行 | 单一 `Dockerfile`（服务器直接托管前端静态文件），另附 `docker-compose.yml` |

## 四种角色

| 能力 | owner | editor | commenter | viewer | 非成员 |
|---|:--:|:--:|:--:|:--:|:--:|
| 读正文/批注/修订/台账 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 改正文（prose） | ✅ | ✅ | ❌ | ❌ | ❌ |
| 改样式（style） | ✅ | ✅ | ❌ | ❌ | ❌ |
| 批注：创建/解决/重新挂接 | ✅ | ✅ | ✅ | ❌ | ❌ |
| 回滚到检查点 | ✅ | ❌ | ❌ | ❌ | ❌ |
| 邀请/改角色/移除成员 | ✅ | ❌ | ❌ | ❌ | ❌ |

浏览器按角色门控命令（正文 `contenteditable`、样式按钮、批注按钮、回滚按钮、成员管理面板）；
**服务器对每个批次独立、整批重新授权**，前端门控只影响易用性，不是安全边界。

## 断连被降级/移除 → 隔离草稿 → 显式重新提交

1. 断连期间产生的编辑以一个**批次**为单位本地应用、入队、落 `localStorage`。
2. 与此同时 owner 把该成员降级或移除（成员变更推进 `authzEpoch` 并写台账）。
3. 重连补发时，服务器在单个同步临界区内读取该成员**当前角色/当前纪元**，对整批做 `GOV.checkBatch`：
   - 任一操作越权（或身份已被移除）⇒ 整批拒绝：不 apply、不分配 seq、不产生修订、不向房间广播内容；
   - 批次整体写入持久化**隔离区**，记录被拒时角色、纪元、越权明细、`fromRole→role`（或"已移出空间"）说明。
4. 浏览器收到 `rejected` 后把该批从本地 CRDT 摘除（基于"已确认操作 + 其余待裁批次"重建），保证越权内容在本地也不残留；批次原文以只读 JSON 文本框展示，可阅读、可复制。
5. 仅当当前角色重新具备足够权限时，"显式重新提交整批"按钮才可用；提交按当前纪元重新授权，成功则作为普通修订恰好合并一次（重复点击/重启后重试均幂等）。

## 运行

```bash
# 本地
npm start          # http://localhost:8080  （PORT 环境变量可改端口）

# 测试（23 项集成测试：同步/离线合并/评论悬空/格式/恢复/重启 + 全部治理验收场景）
npm test

# Docker
docker build -t collab-doc .
docker run -p 8080:8080 -v collab-data:/app/data collab-doc
# 或
docker compose up --build
```

打开 `http://localhost:8080`（可加 `?doc=xxx` 使用不同空间）。页面顶部可改显示名，并显示你的用户 ID（本地生成）；
把用户 ID 告诉空间所有者即可被邀请到指定角色。多开几个窗口即多人协作；开 DevTools 离线模式可验证断网编辑、
降级/移除后重连的隔离与重新提交。

## 架构

```
collab-doc/
├── shared/gov.js       # 角色/权限判定内核（浏览器与 Node 共用）：命令矩阵 + 整批授权
├── shared/crdt.js      # 共享 CRDT：RGA 文本 + 相对位置锚点 + 格式 LWW + 评论状态解析
├── server/server.js    # 静态服务 + 手写 RFC6455 WebSocket + 全局 seq + 成员表/纪元/台账/隔离区/幂等索引 + JSON 落盘
├── public/             # index.html / app.js / style.css（contenteditable 编辑器 + 成员/隔离/台账面板）
├── test/test.js        # 多客户端集成测试（含模拟离线、降级/移除、重启、旧空间并发首开）
└── Dockerfile / docker-compose.yml
```

### 同步与治理协议

- 连接发送 `hello{uid,name,doc,lastSeq}`，服务器回 `welcome{ops,revs,role,epoch,members,audit,quarantine}`；
  旧空间首个 hello 原子认领 owner。
- 内容以批次发送 `ops{batchId,ops,lastKnownRole}`：
  - 放行 → 广播 `ops{applied,rev,epoch,batchId}`；
  - 拒绝 → 仅向本人发 `rejected{quarantine}`（含完整草稿与原因），全员收 `gov`（各自只可见自己的隔离草稿）与一条 `audit`；
  - 重复 `batchId` → `batch-ack` 回首次结论，绝不重复执行。
- 成员管理 `member{mId,action:invite|role|remove,uid,role,name}`：仅 owner；成功广播 `gov`+`audit`，相同 `mId`/同角色重试幂等。
- 显式重新提交 `resubmit{qid,batchId}`：按当前角色/纪元重新授权，成功则放行并写 `quarantine-released` 台账。
- 回滚 `restore{rev}`：仅 owner；非 owner 被拒、不产生修订、台账留痕（重复尝试幂等）。
- 所有治理状态（成员表、`authzEpoch`、审计台账、隔离区、幂等索引）随空间 JSON 原子落盘，重启后重放恢复。

### 关键设计取舍

- **不用任何 npm 依赖**：WebSocket 协议、CRDT、治理均手写，镜像构建无需联网，`node:20-alpine` 即可运行。
- **批次是授权与隔离的最小单位**：不做"逐条放行"，避免一个意图被部分泄漏到共享状态。
- **单线程原子性**：服务器无 `await` 地在同一临界区内完成"读当前角色/纪元 → 判定 → 应用或隔离 → 记账"，
  故角色变更与在途批次无论消息到达顺序如何，裁决唯一且全员一致；统一 `seq` 给出台账↔修订的确定顺序。
- **恢复快照只含文本+格式**：评论不随恢复回滚——锚定文字被恢复操作删除的评论进入可解释悬空状态，可重新挂接。

## 已知限制（演示级）

- 用户 ID 由浏览器本地生成、自报（无密码/会话鉴权）；权限模型是空间内授权，不是身份认证；
- 单进程内存 + JSON 落盘，未做水平扩展；修订快照为全量文本，适合中小文档；
- 编辑器基于 contenteditable + 前后缀 diff，IME 组合输入已做基本处理，复杂嵌套富文本（表格、图片）未支持。
